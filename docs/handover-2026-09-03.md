## The testimonial faults, because both were invisible

Reported as one problem, they were two, and what matters about both is that **every
automated check stayed green throughout.**

### 1. A wanted testimonial published and appeared nowhere

Paul Ruane, Community Development Director for the City of Oak Forest, was written in the
Studio with the "Written consent on file" box unticked — its initial value.
`TESTIMONIALS_QUERY` filters on `consentOnRecord == true`, so the document published
cleanly, validated, reported success, and then existed on no page, with no message
anywhere.

`required()` was not protecting this. **On a boolean, `required()` rejects `null` and
`undefined` and accepts `false`** — which is the initial value — so it permitted exactly
the case that mattered. `consentOnRecord` now carries a `.custom()` rule that refuses
anything but `true` and explains why in the message.

`npm run test:content` *did* catch it, and that is the gate working as designed: it failed
on "publishes no testimonial without recorded consent". But it runs at release, not at the
edit, so it caught the mistake days after it was made.

### 2. The Studio showed placeholder text over two real testimonials

This is the nastiest shape a fault has taken in this project.

`buildDocuments()` `createOrReplace`s the two seed testimonials to
`drafts.testimonial-sample-1` and `-2`. The **published** documents of those same ids had
already been replaced with real testimonials on 2026-08-31. The migration then wrote
placeholder scaffolding on top of them *as drafts* — and Sanity's Studio shows the draft
whenever one exists. So opening either testimonial showed "Sample entry — replace with a
real name" rather than what the author had written.

The published documents were untouched. So the site went on rendering the real
testimonials, and **the build, the unit suite, lint, Lighthouse, the release gate and the
deployed page were all unaffected and all green.** It was visible only by opening the
Studio. It sat there from 2026-08-31 to 2026-09-03 and was found by a person, not by a
test.

The seed now consults `sampleTestimonialDrafts(publishedIds)` and skips any sample whose
published document already exists — matched on the sample ids alone, so a testimonial
written from scratch in the Studio, which gets a generated id, never suppresses a sample
it has nothing to do with. The unscoped dry run now prints `skip` for both and the payload
is 30 documents rather than 32.

## The rules that matter most

**1. Applying a Sanity migration ahead of its code is safe for an ADDED field and breaking
for a MOVED or REMOVED one.** Exercised correctly again this session: `headerCta` was
applied to production first, the live site was confirmed still rendering `Get Started` from
the deployed build, and only then did the code ship. Full account in
`docs/deploys-and-migrations.md`.

**2. `scripts/migrate-content.mjs --apply` with no `--only` is a full content reset**, not
a backfill — `createOrReplace` over every property, post, team member and testimonial from
the seed constants. Scope it:
`--only=<carousel|pages|seo|headings|header-button|cta>`. `cta` is a REMOVAL. The flag
fails closed: a typo, a bare `--only`, or two of them all refuse rather than falling
through to the full run.

**3. Sanity's `validation` is Studio-side only.** The new consent rule closes the Studio
path and nothing else — a script, Vision, the API or an import can still publish an
unconsented testimonial. That is why `content-integrity` is the thing actually protecting
the site, and why the site query filters on the flag rather than trusting the document.

## Traps found this session

All added to the README.

- **`required()` on a boolean accepts `false`.** It rejects only `null` and `undefined`.
  That is the difference between a field that looks gated and one that is, and on
  `consentOnRecord` the ungated value was also the initial value.
- **A migration that writes a DRAFT can hide a published document without touching it.**
  Everything automated stays green, because the published document is intact and it is
  what the site renders. Only the Studio shows the difference, and only to whoever opens
  that document. **If someone says the CMS is showing them the wrong content, query
  `*[_id in path("drafts.**")]` first.**
- **`setIfMissing` keys on absence, not on falsiness.** A leaf holding `''` is falsy but
  present, so a step that decides what to fill by falsiness and then writes it with
  `setIfMissing` reports a repair it did not make — and reports it again on every future
  run. Match the predicate to the mutation, or `set` the leaves you found blank.
- **A longer header label wraps the header.** "Invest With Us" is 14 characters and takes
  the header from 62px to 102px at 768–799px, putting the wordmark on its own row. It wraps
  the way `flex-wrap gap-y-3` was written to and still clears the hero eyebrow by 61px, so
  it is not a defect — but it is a visible change at iPad-portrait width that no test or
  audit reports. `headerCta.label` is capped at 20 characters for this reason; the
  measurements are in the schema comment next to the cap.
- **A test that pins CMS copy fails when someone edits their own copy.** Two E2E tests went
  red from Studio edits rather than from code: the homepage headline accent was changed to
  "chose to live in", and two articles were published with capitals in their slugs. Both
  were intentional. Assert the shape of the content, not the wording.

## Measurement, because it has bitten repeatedly

Byte budgets are stable and trustworthy. **Lighthouse's performance score against the
deployed site is not:** seven runs of the same commit returned 87, 87, 87, 97, 98, 87, 87
on an identical payload. Take at least five samples before believing a delta, and never
compare a `localhost` run against a deployed one.

`npm start` does **not** replace a server already on port 3000 — the old process keeps the
port and keeps serving the previous build. Kill the listener first:
`netstat -ano | grep :3000`, then `taskkill //PID <pid> //F`.
