### The chart's figures are sourced, and that is a rule now

The brief asked for example content to be replaced later. Example *prose* is safe to seed —
a reader can tell an opinion from a fact. A chart cannot be: a bar labelled 3.1% reads as
measurement whoever typed it. So the bars carry Apartment List's published June 2026
year-over-year metro figures, and **`marketSource` is required by the schema the moment a
single bar exists, with the page refusing to render the section without it.** Two guards,
because Sanity validation is Studio-side only.

**If you replace the numbers, update `marketSource` in the same edit or the section
disappears.** That is deliberate.

### Three literals came off the chrome

Found while checking whether the new page was really CMS-driven — it was, but its
neighbours were not.

1. **`MetricBars` defaulted `unit` to `'%'`.** Unreachable *and* misleading: a JS default
   fires only on `undefined`, and the page passes `copy.marketUnit` from GROQ, which
   returns `null` for an empty field. The page never received it; only the tests did. The
   default now lives in the schema as `marketUnit`'s `initialValue`, where an editor can
   see and clear it.
2. **The footer hardcoded all six of its labels.** It now reads five from `navLabels` — the
   same object the header gets — and `/investors` carries its own required leaf,
   `footerLabels.investors`, because it is not in `NAV_TREE`. `/about` takes the tab's own
   `aboutUs` label, so the footer reads "About Us" rather than "About".
3. **`CtaBand`** read `copy?.submitLabel ?? 'Keep me posted'` and hardcoded
   `'Email address'` — the last literals on the site's only conversion path. Both are now
   required content, which made the fallback unreachable as well as wrong.

### Two migrations, applied 2026-09-11

`chrome-labels` (`footerLabels.investors`, `ctaBand.emailLabel`) and `strategy` (the page's
four new sections). Both idempotent, both re-run clean.

   because every `navLabels` leaf is required content and the layout throws before a page
   renders. But the right order is read the reasoning, then disagree with it.

## Rules and traps this session paid for

Each of these is now either enforced by a test or written into a docblock at the point of
use.

1. **A number in a chart is not the same kind of content as a sentence.** Placeholder prose
   is honest scaffolding; a placeholder bar is a fabricated statistic on an investor-facing
   page. This is why `marketSource` is conditionally required and why the section will not
   render without it.
2. **A JS default fires only on `undefined`, and GROQ returns `null`.** Any
   `prop = 'fallback'` on a component fed by Sanity is dead code that still reads as an
   opinion. This has probably bitten before and will again.
3. **Adding a required leaf inverts the migration ordering rule.** Additions are normally
   safe to apply early and harmless late. A required one is safe early and *fatal* late —
   `missingLeaves` throws in the layout, which renders on all 29 pages, so deploying ahead
   of the backfill fails the build for the whole site rather than one page. Now a row in the
   checklist in `docs/deploys-and-migrations.md`.
4. **`setIfMissing` did its job and it changed the outcome.** Production already had a
   two-paragraph Why Midwest body Hunter had written in the Studio; the seeded three-
   paragraph version never landed. That is the guarantee working, but it means **the seed in
   `em8-content.mjs` and the live document differ, and the seed is not what the site
   shows.** Read the dataset, not the seed, when you want to know what a page says.
5. **A grep for a fact is not a check for a fact.** The "Content EM8 owes" list in the last
   handover carried an item for four `teamMember.role` edits. All eight are populated, and
   have been. The list said "unchanged from 2026-09-09" because it was copied forward, not
   verified. Every item in this handover's open list was queried against the live dataset
   today.
6. **The README's "Read these first" pointer went stale, again.** It still named
   `handover-2026-09-09.md` while `handover-2026-09-10.md` sat beside it — the exact trap
   recorded at README line 329. Updated in this PR. **If you write the next handover, change
   that row in the same commit.**
7. **A Bash heredoc in this environment chokes on long TSX.** Two attempts to write a test
   file with `<<'EOF'` failed with an unterminated-quote parse error before the file was
   created. Use the Write tool for anything substantial.
8. **`playwright.config.ts` reuses `.next` when `BUILD_ID` exists** — carried forward from
   the last handover because it is still true and still silent. `rm -rf .next` before a
   measured E2E run.

## Deploying

Auto-deploy is off. Merging ships nothing. The full sequence:

1. Apply any migration **first** if it adds a required leaf (see trap 3 above), and confirm
   a second dry run reports nothing pending.
2. Merge the PR. `gh pr merge` fails locally from a worktree with
   `fatal: 'main' is already used by worktree` **while succeeding on GitHub** — confirm with
   `gh pr view <n> --json state`.
3. Schema changed? `bash scripts/deploy-studio.sh`, from merged code, and check
   `SANITY_STUDIO_PROJECT_ID` appears in the inlined-variables list.
4. Trigger the deploy. `RAILWAY_API_TOKEN` lives in the **repo root's** `.env.local`, not
   the worktree's, and the header is `Project-Access-Token`:

```bash
node --env-file=/c/Users/Kathy/Claude/em8-website/.env.local -e 'const q=`mutation { serviceInstanceDeploy(serviceId: "5d00810f-87c2-4254-963e-b654812d53fd", environmentId: "4260bc70-c3ea-448f-ad04-6541f3acc773", latestCommit: true) }`; const r=await fetch("https://backboard.railway.com/graphql/v2",{method:"POST",headers:{"Content-Type":"application/json","Project-Access-Token":process.env.RAILWAY_API_TOKEN},body:JSON.stringify({query:q})}); console.log(JSON.stringify(await r.json()))'
```

5. Poll for a deployment whose `meta.commitHash` is **yours**. `SUCCESS` arriving for the
   previous commit at the first poll has happened on three separate PRs.
6. Verify on the live site by **content** — a string a visitor would read — not by the
   deploy reporting success.
