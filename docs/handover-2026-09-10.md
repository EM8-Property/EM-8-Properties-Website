## The clearance invariant, derived rather than assumed

Across 40 measurements — four routes × five viewports × fonts loaded and blocked:

> **`clearance = (reservation − header) + slack`,  with `slack ≥ 0`**

So **clearance is floored at `reservation − header`** and cannot go negative from extra overlay
content. `/about` sits exactly on that floor at every phone width (192 − 113 = 79;
144 − 88.5 = 55.5) because its overlay already exceeds the `min-h-[420px]` floor, so its box is
content-driven and grows *downward*.

**This corrects the 2026-09-09 handover's central fear about PR 4.** That document warned a
larger headline would make bottom-aligned CMS copy "climb" into the header. It does not climb —
the box grows. **The real cost of a bigger headline is scroll, not clearance**, which puts §7
in competition with §6 rather than with `headerReservation.ts`. This holds only while the hero
stays `min-h` and the overlay stays in flow; an E2E test now pins it.

Worst clearance on the site remains `/about` at **+31px**, 390px with webfonts blocked,
untouched by this PR. `/` is +81.5px blocked.

## Two defects found by measuring the rendered page, both invisible to every gate

Same lesson as the last two sessions: `next build`, the unit suite, `tsc`, ESLint and
Lighthouse were green through both.

### 1. Desktop stat cells crushed to 45px

`StatBand`'s `lg:` five-column rule is keyed to the **viewport**. Inside the hero overlay the
band lives in a `max-w-[42ch]` container measured at **424px**, so at viewport ≥1024px five
columns gave **45px per figure** — under the ~75px the component's own docblock calls a crush.
`$100M+` and `36.2%` did not fit. No horizontal overflow, so nothing else could catch it.
Phone was never affected (390px → `grid-cols-2` → 131px per cell), which is exactly why the
review-viewport pass looked clean. **Spec §11 keeps desktop as the regression check; this is it
earning its place.**

### 2. The same defect survived in the other branch, because the first fix used the wrong axis

The fix was scoped to `tone="onPhoto"` — tying a **layout** decision to a **colour** one.
`PageHero`'s no-photography fallback passes `tone="default"` while rendering in the *same* 424px
box, so it restored the five-column rule. Reachable whenever `siteSettings.heroCarousel` is
emptied or every slide's property reference dangles — a state `PageHero`'s own docblock calls
reachable on any of the seven pages.

**`StatBand` now takes an independent `columns: 'measure' | 'narrow'` prop; `tone` means only
colour; `PageHero` passes `narrow` in both branches.** Pinned by a fallback-with-stats test and
an axis-independence test. **The rule worth keeping: a container-width decision must not be
keyed to a viewport breakpoint or to an unrelated prop.**

## Rules and traps this session paid for

1. **A container-width decision must not be keyed to a viewport breakpoint**, and must not
   ride on an unrelated prop. Both halves of the stat-crush defect were this.
2. **`naturalWidth` is NOT the bitmap width when `srcset` uses `w` descriptors.** The browser
   reports it density-corrected: a genuine 1600px hero asset reads **649** at DPR 3 and 1299 at
   DPR 1, because 1600 ÷ (3840 ÷ 1560) = 649. Reading it alone sends you chasing a 650px image
   that does not exist — that happened here and produced a wrong conclusion about the hero's
   sharpness before it was caught. Read the URL, or divide the density back out.
   `scripts/measure-phone.mjs --images` prints the inputs rather than inventing a number.
3. **`SUCCESS` from Railway is not evidence, and this session saw exactly why.** At the first
   poll after triggering, the most recent deployment reporting SUCCESS was `e4fbfd1` — the
   *previous* one. A poll trusting the word would have reported done immediately. Match
   `meta.commitHash`.
4. **A deliberately-red release gate must be correlated, not unconditional.** The
   `offeringsHeading` gate was first written to require the title always; the schema
   deliberately permits it to be empty, so it would have gone permanently red the day the last
   offering closed — a legitimate state. It now asserts the title only when
   `count(publiclyOffered && published) > 0`. A gate that is red forever is a gate nobody reads.
5. **A skipped test is honest; a vacuous passing test is not.** The offerings-geometry E2E was
   skipped with a stated reason while the dataset field was empty, then ran and passed after
   the migration. This repo has a documented fault where a test that performed a gesture and
   asserted nothing looked like coverage and hid a bug for a session.
6. **`playwright.config.ts` reuses `.next` when `BUILD_ID` exists.** A stale `.next` from
   before your last commit is tested silently — the old trap in a new costume. `rm -rf .next`
   before a measured E2E run, and remember `npm start` does not replace a server already on
   port 3000.
7. **`gh pr merge` still fails locally** with `fatal: 'main' is already used by worktree` while
   the merge succeeds on GitHub. Confirm with `gh pr view <n> --json state`.
8. **The `build` CI rows register late.** `gh pr checks --watch` exits before they appear; poll
   until no row reads `pending`. Two workflows, four rows.

### Four more, paid for by PRs #31 and #32

All four are in `README.md` under "Found on 2026-09-10" except the last, which is here only.

9. **A crop cap cannot outrun its source asset, and Sanity does not upscale.** Raising
   `urlForImage(...).width(N)` above a source's real width silently returns the source width.
   Check what the source is before spending a budget on a cap: the Sanity URL carries it as
   `-(\d+x\d+)\.`.
10. **`lighthouse-budget.json` declares `/*` but `scripts/lighthouse.sh` only loads `/`.**
    Every other route is in scope by declaration and unaudited in fact. That is how a 2289 KB
    total on `/portfolio` sat unreported against a 2200 KB budget. Measure that page by hand
    whenever images move.
11. **Five Lighthouse runs of one unchanged build scored 75, 84, 91, 79, 79** — a 16-point
    spread — while the image-byte figure was 757 KB in all five. Byte budgets are the stable
    measurement; the score is not. Never read a delta off one run.
12. **A measurement sweep that edits a class and rebuilds must verify the edit landed.** The
    first attempt at PR #31's type sweep interpolated the current token into a `sed` pattern;
    when that token was `text-[40px]`, `[40px]` became a regex character class, the
    substitution silently did nothing, and three candidates would have been reported at four
    different labels while measuring the same size. It was caught by the script echoing the
    applied class. **A sweep that does not assert its own mutation is a sweep that can report
    four identical rows as four measurements.**
